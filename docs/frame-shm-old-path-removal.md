# Removing the Pre-Frame-SHM Video Path

Closes out the frame-shm-ingest project (spec
`docs/superpowers/specs/2026-07-22-frame-shm-ingest-design.md`, plan
`docs/superpowers/plans/2026-07-22-frame-shm-ingest.md`): the A/B gate the
acceptance bench ran behind is gone, and whole-frame ingest is the only video
path. This is the follow-up commit the spec called for ("Not a permanent dual
transport"), same shape as the async-FEC-worker gate removal before it.

Acceptance evidence for the path that survived lives in
[frame-shm-bench-acceptance.md](frame-shm-bench-acceptance.md) (all gates) and
[frame-shm-rtp-packetization-efficiency.md](frame-shm-rtp-packetization-efficiency.md)
(the 2x-pps packetizer finding, fixed + hardware-verified).

## What the video path is now

```
waybeam venc → frame-shm ring (whole Annex-B frames + VencFrameMeta)
  → FrameSource (drone) → FramePipeline: classify_frame + producer IDR flag,
    FrameHdr stamped over the meta region in place
  → UepEncoder::add_frame: 6-byte FRAG → sliding-window FEC, window SEALED at
    frame end → SbiPacker → TxQueue → radio
  → GS: UepDecoder emits raw fragments → FrameStream (cross-layer ordering by
    frame_id, streaming prefix emission, gap timeout) → RtpPacketizer (RFC 7798,
    PT 97, ssrc "MABR") → UDP :5600
```

One wire format, one ingest, no mode selection anywhere.

## What was deleted

| Area | Gone |
|---|---|
| Drone | `RingSource`, `drone/vendor/venc_ring.{c,h}`, the `video_input` gate and its `!frame_mode` hot-loop branch, `ring_name` |
| GS | `RtpReorder` (the frame tail orders by `frame_id`; there is nothing left to reorder), the per-session format flip |
| Common | `classify_rtp`, `UepEncoder::add_rtp`, `FragReassembler` (FrameStream assembles instead — a complete-units-only reassembler cannot emit a truncated frame's head), the 4-byte `<HBB>` FRAG format, `UepLayerCfg::wide_frag`, `UepDecoder::set_wide_frag` |
| Tests | `test_ring`, `test_rtp_reorder`, `test_frag_reassembler`, the `classify_rtp` half of `test_nal`, `tests/vectors/frag.json` |
| Fixtures | `tests/fixtures/rtp_stream.bin` → `tests/fixtures/frame_stream.bin` (same NAL payloads, regrouped into 13 access units; generated by `tools/genvectors/gen_vectors.py`) |

`Fragmenter` keeps only the 6-byte `<HHH>` header (`Fragmenter::kHdrLen`), and
`UepDecoder` emits `DecodedFrag` (raw fragments) rather than the old
`DecodedRtp` — the struct name was a lie once the units stopped being RTP packets.
`CAP_FRAME_WIRE` stays on the wire with one legal value: maburd always
advertises it, and maburgs **refuses video** from a session without it (loud
one-line log) rather than feeding mutually unparseable frag headers into
FrameStream.

**Behavior change to know about:** video on the GS now requires an established
session (`SESSION` + the cap). The old build had a format-agnostic fallback that
forwarded packets whether or not rendezvous had completed, so a GS restarted
mid-flight showed video immediately; now it shows video once the drone's DiscAck
lands (one beacon period, ~1 s). This is the spec's "cross-wiring must be
impossible, not merely detectable" trade, taken deliberately: a legacy drone's
fragments fed into FrameStream would render garbage instead of failing visibly.
The decoder keeps consuming bodies throughout, so per-stream stats still move
while the tail is off — `video tail -> off (no session)` in the log is the
witness.

## Config migration

`video_input` and `ring_name` are **accepted and ignored** with a WARNING line,
for one release:

```
maburd config: WARNING: 'video_input' is obsolete and ignored — video ingest is
frame-shm only (frame_ring_name). Remove it from this config.
```

This deliberately diverges from the `fec.async_worker` precedent (which throws
on a stale key). The bench procedure pinned `video_input` in the drone's live
`/etc/mabur.json`, so throwing would leave an upgraded maburd unable to start —
no video at all, on a device you may not be able to reach quickly. Remove both
keys from `/etc/mabur.json` at your convenience; `bundle/mabur.default.json`
already ships only `frame_ring_name`.

waybeam must be on `frame-shm://` — that has been the deployed setting since
acceptance. maburd still cross-checks `outgoing.server` at startup and logs
`FATAL MISMATCH` (without exiting) if it is not, so a half-migrated drone
screams instead of sitting silently unattached.

The GS needs no config change.

## Rollback

The gate is gone, so rollback is binary-level only — the
`.pre-frameshm` copies from the acceptance deployment, per section 4 of
[frame-shm-bench-acceptance.md](frame-shm-bench-acceptance.md). If you restore
a pre-frameshm maburd, restore the matching `/etc/mabur.json` (with
`video_input: "ring"`) and point waybeam back at `shm://mabur`; a new maburgs
paired with an old maburd refuses video by design, so roll both devices back
together.

## Test + bench changes worth knowing

- **Host e2e** (`tests/integration/run_host_e2e.sh`) feeds the frame fixture
  through `maburd --dry-run` and decodes with devourer's Python reference
  (`tools/bench/decode_bodies.py`, now 6-byte FRAG + frame-unit reassembly,
  matching frames by the `frame_id` maburd stamped). Frame units round-trip
  byte-exact, so the FrameHdr and the wide FRAG format are pinned against an
  independent implementation.
- **GS e2e** (`run_gs_e2e.sh`) can no longer compare packets byte-wise: the GS
  builds its own RTP. `verify_rtp.py` depacketizes the output (FU reassembly,
  frames grouped by RTP timestamp, marker bit = complete) and compares per-frame
  NAL lists against the fixture, plus monotonic timestamps and no
  alien/duplicate frames.
- **maburd `--dry-run --in`** now takes a frame file (`u32-LE len |
  VencFrameMeta | Annex-B`), and `--rc-in` record indices count frames, not
  packets. Both dry-run and the real hot thread go through the same
  `FramePipeline`, so a replay exercises the bytes the drone would actually
  send.
- **maburgs `--dry-run`** runs the real frame tail (FrameStream →
  RtpPacketizer) and reports `frames_out: clean/truncated/dropped/bad_frag`.
- **burst_sim** now models whole frames (18200 B at 62.5 fps) instead of a
  1200 B packet stream. This mattered: `add_frame` seals the window per frame,
  so modelling video as many tiny units inflated redundancy far past the
  layer's overhead setting (stream 3 stayed lossless out to B=80 bodies). With
  realistic frame sizes the analytic budget bound holds again — measured edge
  B=21 vs B=20 before. The sim also drops an uncounted 500 ms cooldown tail,
  since the last counted frame needs following traffic for its window to
  complete.
- **fecbench / encbench / gf_bench** feed `add_frame`; `mt_encoder.h`'s replica
  mirrors the frame-end seal, and fecbench's `verify encoder` rows still
  byte-compare it against the real `UepEncoder`.

## Stats-line changes (both daemons)

- maburd: `frame_ring: fill=…% writes=… full_drops=… oversize=… idr_disagree=…`
  (unchanged from the gated build, now unconditional).
- maburgs: `fe=` (FRAG evictions) is gone with the reassembler; `ord[…]` keeps
  `ok/gap/back` but loses `buf/skip/late` (reorder-buffer counters) and now
  measures the packetizer's own output, which is monotonic by construction —
  a gap there means the frame tail regressed. `frames[clean/trunc/drop]` plus
  `badfrag=` are always printed.
